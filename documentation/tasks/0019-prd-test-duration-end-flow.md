# PRD-0019: Test Duration End Flow

> **Created:** 2026-02-04
> **Status:** Draft
> **Priority:** High
> **Estimated Effort:** 20-30 hours (3-4 days)

---

## 1. Introduction/Overview

When a test's allocated time expires, the current system requires teachers to manually click "End Test" to trigger student submissions and session cleanup. This creates several issues:

1. **Students may exceed allotted time** if teacher is distracted or forgets
2. **No automatic result delivery** - students wait indefinitely after time expires
3. **No accommodation awareness** - teachers can't easily see which students have extra time
4. **Session state ambiguity** - unclear what happens when base time ends but accommodated students continue

This PRD defines an automated, skill-aware flow for handling test duration expiry that properly manages both base students (no accommodation) and accommodated students (extra time), while preserving the session for reuse.

---

## 2. Goals

| Goal | Metric |
|------|--------|
| **Automatic submission when time expires** | 100% of student answers captured within 10 seconds of timer end |
| **Immediate result delivery** | Listening/Reading students see results within 5 seconds of submission |
| **Accommodation support** | Students with extra time can continue uninterrupted after base timer ends |
| **Session preservation** | Sessions remain reusable for additional tests after completion |
| **Teacher awareness** | Clear visual indication of remaining accommodated students |

---

## 3. User Stories

### Student Stories

| ID | Story |
|----|-------|
| S1 | As a student, when the test timer reaches 0, I want my answers auto-submitted and locked so I don't accidentally lose work |
| S2 | As a **Listening/Reading** student, after auto-submission I want to see my results immediately so I can learn from my mistakes |
| S3 | As a **Writing** student, after auto-submission I want to see a confirmation that my work was submitted and is pending teacher review |
| S4 | As a student with extra time accommodation, I want my test to continue after the base timer ends so I can use my full allotted time |
| S5 | As a student, after completing my test I should not be able to rejoin and modify answers |

### Teacher Stories

| ID | Story |
|----|-------|
| T1 | As a teacher, when the test timer reaches 0, I want a 10-second countdown warning before auto-end so I can extend time if needed |
| T2 | As a teacher, I want base students auto-submitted when time expires so I don't have to manually end |
| T3 | As a teacher, I want to see which students have extra time remaining with a clear counter so I know when the full session will complete |
| T4 | As a teacher, I want to maintain all controls (pause, extend, end) even after base time expires for accommodated students |
| T5 | As a teacher, when ALL students (including accommodations) finish, I want to be redirected to the results dashboard automatically |
| T6 | As a teacher, I want the session to remain active after test ends so I can run another test with the same session code |

### 4.4 Disconnected Student Handling

| ID | Requirement |
|----|-------------|
| FR-D1 | On auto-submission trigger, the system SHALL check if player is disconnected |
| FR-D2 | For disconnected players, the system SHALL submit their last saved answers from Firebase |
| FR-D3 | The system SHALL determine if the submission is "truly incomplete" by checking: answered questions count < total questions |
| FR-D4 | If truly incomplete, the submission SHALL be marked with `isIncomplete: true` and `submittedBy: 'system-timeout'` |
| FR-D5 | If all questions were answered (even if disconnected), `isIncomplete` SHALL be `false` |

### 4.5 Session Lifecycle

| ID | Requirement |
|----|-------------|
| FR-L1 | `completeBaseTest()` SHALL NOT modify session `status` or `testId` |
| FR-L2 | `endFullSession()` SHALL set session `status: 'waiting'` and clear test-specific data but preserve session code |
| FR-L3 | After `endFullSession()`, the session SHALL be reusable for additional tests |
| FR-L4 | Players with `hasCompletedTest: true` SHALL NOT be cleared; only their answers/scores SHALL be cleared for next test |

---

### 4.6 Post-Test Result Recovery Contract

| ID | Requirement |
|----|-------------|
| FR-R1 | For **IELTS Reading**, **IELTS Listening**, and **THCS** live sessions, student result access SHALL be recoverable from persisted post-test breadcrumbs (`lastTestId`, `lastTestSessionCode`, `lastTestEndedAt`, `lastTestCompletedAt`) even if router state is missing or the page is refreshed immediately after teacher-end. |
| FR-R2 | `StudentWaitingRoomPage` SHALL be the recovery owner for live-session result handoff and SHALL rehydrate the effective release state from the full session snapshot, not only from a transient `reviewReleaseState` navigation value. |
| FR-R3 | Teacher-end redirect state (`showResults`, `testId`, release metadata) MAY be passed as a fast path, but it SHALL NOT be the only source of truth for deciding whether recent results are available. |
| FR-R4 | Listening test pages SHALL ignore transient `waiting` status changes while canonical `testData` is still loaded so the teacher-end redirect path can complete before the student is moved away from the active test surface. |
| FR-R5 | **Writing** remains a teacher-graded path. Submission confirmation and later teacher feedback remain the contract there; immediate post-end result release is not required. |

## 5. Non-Goals (Out of Scope)

| Item | Reason |
|------|--------|
| **Auto-grading for Writing tests** | Writing requires manual teacher evaluation |
| **"All students submitted" notification** | Not needed since auto-end handles completion |
| **Custom countdown duration** | 10 seconds is the fixed warning period |
| **Different grace periods per skill** | 5-second grace period applies to all skills |
| **Partial auto-end (only some students)** | Either auto-end happens for all base students or none |
