## 4. Shared module contract

Use `notificationProducerClient.ts` as the ordinary port and `notificationService.ts` for readers. Public contract: `notifyCommittedEvent(event): Promise<DeliveryResult>`. Features supply domain event/source/occurrence identities, not transports, URLs, arbitrary recipients/text or token providers. Private mapping chooses the route; no plugin framework or old transport-option aliases. Update the signature/callers coherently, activate families independently.

Call after confirmed commit. Shared service catches errors and owns the promise through ordinary navigation; component unmount cannot cancel it. A slow notice cannot keep the action form pending. Logout stops new pages; hard closure can interrupt work. Return confirmed written/already-present, failed, unknown or skipped with reason, and bulk unattempted counts. A success HTTP status alone proves neither complete storage nor a human read.

Use fixed short templates and registered safe destinations. IDs/content/`createdAt` derive from stable committed occurrences, never send time/mutable names. Real repeated actions need distinct occurrences; duplicate callbacks reuse one identity. Reuse domain revisions/IDs; add no generic event ledger.

Direct RTDB sends atomically patch content fields only, omitting `read`; Rules allow create or identical replay, reject content changes/deletion, and preserve recipient read state even through ancestor writes. New ordinary IDs cannot collide with older formats. Absent read means unread; recipient alone may change absent/false→true or true→true while a notice exists, never reset/delete read or create a notice through `/read`.

Privileged bridge sends conditionally create with `If-Match: null_etag`. A412 permits one collision classification/read: identical stable content/time is replay, mismatch is conflict, undecidable is unknown. Ignore only recipient-owned read state. Never overwrite or loop PUTs.

Explicit reminders are delivery requests: consume the existing maximum three reminder requests before sending; failure may consume a request. An intentionally disabled reminder route must not record or consume a request. Say “sent” only for confirmed notices; partial/failed/unknown counts must be truthful. Product save toasts use the shared announcements port.

**Homework reset — 2026-10-01 semantics:** retain the product action that removes the student's attempts and linked results, with truthful partial-cleanup counts. Its one notice announces a proven removed attempt, not a certificate that every attempt/result is gone or that retaking is available. Reuse the existing immutable reset occurrence, bound atomically to one exact deleted submission and its optional linked result ID; no arbitrary all-results list, new reset ledger or trusted bulk-reset engine. The technical reference owns source proof and bounded cleanup checks. Delivery remains detached from product success; no retry/recovery-queue promises.
