## Post-publication verification recovery

Firebase reported successful publication. The first immediate provider response
was rejected by the parser as lacking a finalized live release; the original
command consequently exited nonzero with unconfirmed/unverified journal state.
A later native provider read identified the finalized version, operation ID and
correct source manifest. The original rejected response was not retained, so
its exact missing or inconsistent field is unknown.

The existing `release:verify-existing` route resumed that same operation. It
independently retrieved/validated the retained archive, verified current provider
identity and every manifest-listed asset, settled the local ledger and uploaded and
read back the append-only outcome. Verification exited zero at 00:40:18.
**There was one publication, no rebuild for recovery, no redeployment and no
rollback.** No supplied JSON or manual receipt assertion established success.

## Phase 2 result and remaining limits

This advances the required real normal-release count to **1 of 2**. A passing
planner or CI run did not count. The second release must contain useful qualified
work selected from protected main and needs separate authorization; a docs-only,
empty or duplicate publication must not be manufactured to complete the counter.

Observed approved-executor start to successful resumed verification was about
23 minutes14 seconds; publication began about20 minutes after start. The narrow
Firebase publication itself was about28 seconds. This does not meet the plan's
ten-minute routine-release target. The full convergence verification took7m40s,
the build1m53s, and the retained source is about180 MB. These are measured costs
for proportionate later optimization, not grounds to remove safety checks now.
Repeated native dependency/hotfix checks disappear or simplify when unchanged
main is the production baseline; that benefit still needs actual measurement on
the next useful release. Final-state visibility during long verification also
needs improvement. No second framework was introduced.

The pre-existing active Homework numeric-scorer mismatch remains separate.
Abandoned sessions, cross-device Reading draft sync, historical answer-key repair
and inherited course-material Edit routing remain excluded. Local student proof
used an untimed fixture; browser countdown/expiry proof is not claimed. Native
unsaved-close confirmation automation remained blocked; canonical Listening
edit/save/full reload/reopen passed. The release does not establish live browser
behavior beyond the independent source/asset readback and prior qualified local
flows. Hosting recovery cannot undo backend/data operations, and rollback was
not exercised or authorized by this publication.
